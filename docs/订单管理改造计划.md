# 订单管理改造计划

> 依据 `docs/订单流程.md`，对订单管理界面进行流程化改造。

## 已确认的约定

| 项 | 约定 |
|----|------|
| 订单状态 | `0=未成交`、`1=已录单`、`2=已接单`、`3=已预约`、`4=已上门`、`5=已回访`、`6=已完工`（字典 `order_status` 已建） |
| 角色权限 | 硬编码 + `consts` 集中常量（后续易调整） |
| 详情存储 | `biz_order_details.order_id` 关联 |
| created_by | `xy_biz_order.created_by`（bigint，录单人ID，已加列，实施时用 `gf gen dao` 同步 entity/dao） |
| 实施节奏 | 逐阶段，每阶段验证 |

## 订单流程（6 步）与角色

| 步骤 | 名称 | 操作角色 | 主要字段 | 目标状态 |
|------|------|---------|---------|---------|
| 1 | 录单 | 话务员/话务员管理员 | 排单日期、姓名、可用时间、区域、地址、联系电话、预约业务、到期时间；话务员=当前登录用户 | 1 已录单 |
| 2 | 派单 | 收单员管理员 | 收单员 | 2 已接单 |
| 3 | 预约 | 收单员/收单员管理员 | 收单预约情况 | 3 已预约 |
| 4 | 上门 | 收单员/收单员管理员 | 上门日期、成交业务、携转情况、客户实际姓名、身份证号码、实缴额度、是否乡下单、新开号码、终端串码、附件、话补、是否纯新增 | 4 已上门 |
| 5 | 回访 | 话务员/话务员管理员 | 二次回访情况 | 5 已回访 |
| 6 | 完成 | 财务文员/管理员 | 宽带账号、是否完工、工号 | 6 已完工 |

> `0=未成交` 为终止态（可选）。

## 角色与数据可见性

| 角色 key | 可见范围 | 备注 |
|---------|---------|------|
| `telemarketer` / `telemarketer_manager` | 只看自己录的单（`created_by`=当前用户） | 话务员、话务员管理员 |
| `agent` | 只看派给自己的单（`agent_id`=当前用户） | 收单员 |
| `agent_manager` / `documentary` / `admin` | 看所有单 | 收单员管理员、财务文员、管理员 |

## 角色与操作权限

| 角色 key | 可执行操作 |
|---------|-----------|
| `telemarketer` / `telemarketer_manager` | 录单、回访；删除**已录单**（status=1）的单（逻辑删除） |
| `agent_manager` | 派单；看全部 |
| `agent` | 预约、上门（仅派给自己的单） |
| `documentary` | 完成情况；保留新增/修改 |
| `admin` | 全部；删除任意单（即使已完成） |

## 阶段 1 · 后端基础（权限/状态/可见性/逻辑删除/详情API）

### 1.1 数据库
- `xy_biz_order.created_by`（已加列，bigint DEFAULT 0 COMMENT '录单人ID'）
- `biz_order_details` 表已存在（id 时间戳、order_id、user_id、content、is_deleted），无需新建
- 实施时执行 `gf gen dao` 同步 `created_by`

### 1.2 常量（`server/internal/consts/order.go` 新增）
```go
// 订单状态
OrderStatusNotDeal   = 0 // 未成交
OrderStatusRecorded  = 1 // 已录单
OrderStatusAssigned  = 2 // 已接单
OrderStatusAppointed = 3 // 已预约
OrderStatusVisited   = 4 // 已上门
OrderStatusFollowed  = 5 // 已回访
OrderStatusCompleted = 6 // 已完工

// 角色 key（集中管理）
RoleAdmin               = "admin"
RoleTelemarketerManager = "telemarketer_manager"
RoleAgentManager        = "agent_manager"
RoleDocumentary         = "documentary"
RoleTelemarketer        = "telemarketer"
RoleAgent               = "agent"
```

### 1.3 角色权限助手（`server/internal/logic/bizorder/perm.go`）
```go
currentRole(ctx) string                       // 基于 contexts.GetUser().RoleKey
applyScope(model, role, userId) *gdb.Model    // 数据可见性
canStep(role string, step int) bool           // 步骤权限
canDelete(role string, status int) bool       // 删除权限
```

### 1.4 List 数据可见性
- `telemarketer`/`telemarketer_manager` → `t.created_by = 当前用户`
- `agent` → `t.agent_id = 当前用户`
- 其余 → 全部
- 默认过滤 `t.is_deleted = 0`

### 1.5 分步保存接口
- API：`POST /admin/biz-order/stepEdit`
- 入参 `BizOrderStepEditInp{ Id, Step, 各步骤字段 }`
- logic `StepEdit`：
  - 校验角色 + 当前状态是否允许该步骤
  - 按 `Step` 只更新本步骤字段并推进状态
  - 录单：`created_by`、`telemarketer_id`=当前用户
- 保留原 `BizOrderEdit`（管理员/财务文员全字段编辑）

### 1.6 逻辑删除
- `Delete` → `is_deleted=1`；按角色+状态限制

### 1.7 详情子表 API（`biz_order_details`）
- `GET /admin/biz-order/detailList?orderId=` → 该订单详情列表（含操作人姓名）
- `POST /admin/biz-order/detailAdd` → 新增（`order_id`,`user_id`=当前用户,`content`）
- `POST /admin/biz-order/detailDelete` → 逻辑删除自己的（校验 `user_id`）

### 1.8 审计
- 复用全局 `OperationLog` 中间件；关键状态变更在 logic 记录业务日志

**阶段 1 验证**：`go build` + 迁移/dao 同步 + curl 接口测试。

## 阶段 2 · 前端分步操作

### 2.1 录单按钮 + 录单弹窗

### 2.2 按状态/角色动态操作列
- 列表操作列按 `orderStatus` + `RoleKey` 渲染：派单/预约/上门/回访/完成/删除

### 2.3 分步弹窗
- 每步骤一个弹窗（或按步骤渲染字段的通用弹窗）
- 弹窗内：**保存本步骤字段** + **下一步**（`ElMessage.confirm` 后调 `stepEdit` 推进）
- 管理员/财务文员保留全字段"新增/编辑"

## 阶段 3 · 详情评论区 + 详情页改造

### 3.1 评论区组件 `OrderComment`（可复用）

一个 `OrderComment.vue` 组件，同时用于**详情页**和**所有步骤弹窗**，支持两种展示形态，且**两种形态都包含新增输入框**。

**Props**：`orderId: number`（其余样式类、占位符可配置）

#### 折叠模式（embedded，默认）
> 用于详情页卡片、各步骤弹窗底部。

```
┌───────────────────────────────────────┐
│ 订单评论                     [更多]     │  ← 标题 + 更多按钮
├───────────────────────────────────────┤
│ ● 最新一条评论                          │
│   张三 · 2024-01-01 12:00              │
│   评论内容……（单行截断）                │
│ 无评论时显示「暂无评论」                 │
│ ┌───────────────────────────┐         │
│ │ 输入评论……         [发表]   │         │  ← 新增输入框
│ └───────────────────────────┘         │
└───────────────────────────────────────┘
```
- **默认只展示最新一条**：取 `detailList` 时间正序的最后一条
- 最新一条内容多时单行截断 + 悬停 `title`

#### 全量弹窗模式（点击「更多」打开）
```
┌───────────────────────────────────────┐
│ 全部评论 (12)                           │
├───────────────────────────────────────┤
│ 张三 · 2024-01-01 12:00    [删除]      │  ← 仅自己的评论显示删除
│   评论内容……                           │
│ 李四 · 2024-01-01 13:00               │
│   评论内容……                           │
│ ……（内容多时滚动 / 分页）               │
│ ┌───────────────────────────┐         │
│ │ 输入评论……         [发表]   │         │  ← 与折叠模式相同的输入逻辑
│ └───────────────────────────┘         │
└───────────────────────────────────────┘
```
- 全量弹窗**沿用折叠模式的逻辑**：含新增输入框、仅自己可删除

### 3.2 展示位置
- **详情页**（`detail/index.vue`）：订单信息 `ElDescriptions`（现有）**下方**新增"订单评论"卡片，内嵌 `OrderComment`（折叠模式）
- **所有步骤弹窗**（录单/派单/预约/上门/回访/完成）：底部放紧凑 `OrderComment`（折叠模式），**默认折叠只显示标题 + 最新一条**，点开才展开输入框，避免弹窗过挤

### 3.3 权限
- **新增评论**（`detailAdd`）：不限制步骤/角色，只要能看到该订单（与 List 数据可见性一致）即可新增；`user_id`=当前用户
- **删除评论**（`detailDelete`）：只能删自己（`user_id`=当前用户），逻辑删除，后端强制校验
- **查看评论**（`detailList`）：按 `order_id` 返回全部未删评论（含操作人姓名，时间正序）

### 3.4 后端 API（对应阶段 1.7）
| 接口 | 说明 |
|------|------|
| `GET /admin/biz-order/detailList?orderId=` | 该订单全部未删评论（含操作人 real_name/nickname 回退，时间正序） |
| `POST /admin/biz-order/detailAdd` | 新增（`order_id`,`content`；`user_id`=当前用户） |
| `POST /admin/biz-order/detailDelete` | 逻辑删除自己的 |

### 3.5 实施要点
- `detailList` 排序：`created_at ASC`（最新在最后，前端取最后一条作"最新"）
- 时间展示：`formatTimestamp`；操作人 join `admin_user` 取姓名（real_name→nickname 回退）
- 评论内容：`content` text 字段，渲染纯文本（`white-space: pre-wrap` 支持换行）
- `details` 字段（主表）由评论区承载
