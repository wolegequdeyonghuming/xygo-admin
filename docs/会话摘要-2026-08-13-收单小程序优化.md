# 会话摘要：收单小程序优化（2026-08-13）

> 本文件为一次开发会话的工作摘要。完整设计见《收单小程序设计文档.md》，PC 端操作手册见《order-flow.md》。

## 一、修复

1. **登录失效不自动续期**：小程序 `utils/request.js` 只认 `code===401`，而后端未授权码为 `61`（`gcode.CodeNotAuthorized`）。改为识别 `61`（刷新重放）、`10010`（被踢下线清会话跳登录），并加「单飞」防并发刷新。
2. **PC 录单并下一步报 `sql: no rows`**：`handleStepSubmitNext` 用 `formData.id`（新增时为 0）调 stepNext。改为使用 `stepEdit` 返回的新订单 id（`res?.id ?? formData.id`）。小程序端无新增流程，无此问题。
3. **排单选收单员报 SQL 歧义/列不存在**：`UserAgents` 查询中 `id` 与 JOIN 表歧义、`xy_admin_role.status` 别名未生效。修复为 `xy_admin_user.id` 限定表名、`r.status` 用别名。
4. **附件跨端显示全乱**：`attachment_id` 两套格式混存（PC 存 URL、小程序存 ID）。统一为**只存数字 ID**，订单接口**联查 `sys_attachment` 返回 `attachments:[{id,url,name,size,mimetype}]`**；PC 附件组件新增 `valueType="id"` 存 ID；小程序详情/收单直接用联查对象。新增后台接口 `GET /admin/attachment/listByIds`（PC 组件回显用）。
5. **H5 图片带 `/m` 前缀**：uni-app H5 `<image>` 会为 `/` 开头 src 拼接路由 base。改独立端口部署 + base `/` 后自然消除。
6. **待处理/已处理 文案与配色**：统一为 待收单/已收单，配色改为 未收单橙、待收单红、已收单蓝。

## 二、功能 / 权限

- **收单员管理员**可看全部单，但**预约/收单仅限收单员为自己**的单（后端 `canAgentManagerAppointCollect` + 前端 `canCollect`）。
- **管理员/文员**不能排单/预约/收单（仅查看与完工）；完工需订单已收单（status≥4），未收单不可完工；**文员与管理员工完工权限一致**。
- **话务员录单只能「保存」纯新增**（PC 弹窗按 `canStep(step)` 控制「保存并下一步」显隐，顺带修复完工/收单等步骤误隐藏问题）。
- **详情页字段对照 PC 显示全**（收单 12 项、完工含备注、区县/到期/排单日期/创建/更新时间，保留状态门控）。
- **详情页操作按钮改为固定底栏**（`position: fixed` + `z-index: 100`，弹窗 z-index 2000 覆盖其上，`env(safe-area-inset-bottom)` 安全区）。
- **非图片附件单独处理**：新增 `utils/attachment.js`，`isImage` 按 mime/扩展名判断；图片预览、非图片显示文件卡片，H5 `window.open`、微信 `downloadFile + openDocument`。
- **去掉 statusBarHeight 计算**：全部页面改为固定 `padding-top: 20px`。

## 三、部署架构（关键决策）

- **3006 = 统一后端网关 + 管理后台**：`/admin /staff /member /site /system /captcha /attachment /socket` 全部代理 4096；正式微信包与 H5 跨域请求均打到这里，正式发布将 `listen 3006` 改为 `443 ssl` + 域名，**单一入口**。
- **3007 = 小程序 H5 纯静态**（`deploy/nginx.uni.conf`）：仅 `location /` 服务 `/home/fpd/m/`，**零代理**；H5 的 API/图片跨域调 3006。
- **H5 基路径 `/`**（manifest `h5.router.base`），不再用 `/m/`。
- **环境变量**：`VITE_API_BASE`（小程序端）、`VITE_H5_API_BASE`（H5 端，dev 留空走 vite 代理，prod 指向 3006）。
- **CORS**：后端已有 `middleware.CORS`（含 `Authorization`、预检 OPTIONS 先于鉴权返回 204）。开发 `corsOrigins:[]` 全放行；生产在 `config.yaml` 的 `security.corsOrigins` 加入 H5 来源。微信原生请求无 Origin 不受影响。**无需改后端代码、无需 nginx 配 CORS**。
