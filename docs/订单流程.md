# 订单流程
1. 【话务员/话务员管理员】录单（新增）：
- 排单日期、姓名、可用时间、区域、地址、联系电话、预约业务、到期时间、话务员（自动填写当前登录的话务员用户）
2. 【收单员管理员】派单：
- 收单员（选择收单员用户）
3. 【收单员/收单员管理员】预约：
- 收单预约情况
4. 【收单员/收单员管理员】上门：
- 上门日期、成交业务、携转情况、客户实际姓名、身份证号码、实缴额度、是否乡下单、新开号码、终端串码、附件、话补、是否纯新增
5. 【话务员/话务员管理员】回访：
- 二次回访情况
6. 【财务文员/管理员】完成情况：
- 宽带账号、是否完工、工号

# 说明
## 权限
1. 【话务员】、【话务员管理员】只能看到自己录的单；
2. 【收单员管理员】、【财务文员】、【管理员】能看到所有的单；
3. 【收单员】只能看到派给自己的单；
4. 以上【】都关联角色key，具体如何实现需要确定方案，是硬编码还是配置保持灵活性。
5. 【话务员】、【话务员管理员】可以对未排单的订单进行删除操作（逻辑删除），管理员可以对所有单进行删除，即使已完成

## 界面
1. 根据订单状态，展示不同的操作按钮；
2. 点击按钮，拆分成多个弹窗，进行录入操作；
3. 【财务文员】、【管理员】保留原有的新增、修改按钮；
4. 顶部新增按钮位置增加录单按钮，对应流程第1步录单；
5. 每一个步骤，都可以多次保存本流程的字段（修改），然后还有一个（下一步）的按钮，点击这个按钮，ElMessage.confirm后再进行到下一个步骤。

## 详情字段
1. 目前订单主表中，详情字段用的是varchar，在编辑中展示的是input；
2. 修改为类似于“评论区”的组件，不同用户可以更新详情，并留痕；
3. 详情表id使用时间戳，用逗号隔开记录到订单主表中；
4. 用户可删除自己的详情（逻辑删除），不能修改，不能删除别人的详情；
5. 需要判断是在主表中的details字段关联，还是详情表中的order_id关联。

## 日志
1. 每个操作都要留痕

## 已有详情表结构

DROP TABLE IF EXISTS `xy_biz_order_details`;
CREATE TABLE `xy_biz_order_details`  (
  `id` bigint NOT NULL COMMENT '主键',
  `order_id` bigint NOT NULL COMMENT '订单id',
  `created_at` bigint NULL DEFAULT NULL COMMENT '创建时间',
  `updated_at` bigint NULL DEFAULT NULL COMMENT '修改时间',
  `user_id` bigint NULL DEFAULT NULL COMMENT '操作人',

) COMMENT = '订单详细情况描述表';
