## 1. 项目概述

- 产品定位：为话务员、收单员、收单员管理员、文员、管理员等角色提供订单录入后的**收单流转工作台**（排单 → 预约 → 收单 → 完工）。
- 多端形态：
  - **微信小程序**（mp-weixin）：`npm run build:mp-weixin`
  - **H5 网页**（浏览器/手机访问）：`npm run build:h5`，经 nginx 部署在 `/m/` 路径。
- 后端复用 XYGo Admin 的**后台 admin 用户体系**（`xy_admin_user` + 角色），通过 `/staff/*` 一组新接口与 `StaffAuth` 中间件提供服务，单二进制部署天然支持。

## 3. 角色与权限

### 3.1 可登录角色

`StaffAuth` 中间件（`server/internal/middleware/staff_auth.go`）放行的角色：

| 角色 key | 名称 | 说明 |
|----------|------|------|
| `telemarketer` | 话务员 | 录单（PC 端）、回访 |
| `telemarketer_manager` | 话务员管理员 | 同话务员 |
| `agent` | 收单员 | 预约、收单 |
| `agent_manager` | 收单员管理员 | 排单、预约/收单（仅收单员为自己） |
| `documentary` | 文员 | 完工（PC/小程序均可） |
| `admin` | 管理员 | 完工；不参与排单/预约/收单 |
| `super_admin` | 超管 | 全量权限（豁免大部分限制） |

### 3.2 鉴权流程

1. `/staff/auth/login`、`/staff/auth/refresh` 放行。
2. 其余 `/staff/**` 必须携带 `Authorization: Bearer <accessToken>`。
3. token 解析失败 → `code 61`（`gcode.CodeNotAuthorized`）「登录已失效，请重新登录」；被踢下线 → `code 10010`「您的账号已在其他设备登录，请重新登录」；角色不在白名单 → `code 62`「无权限访问收单小程序」。
4. 校验通过后注入用户上下文（`contexts.SetUser`），复用后台 admin 用户体系，`bizorder` 权限逻辑自动生效。

### 3.3 数据可见性（List / Stat）

`server/internal/logic/staff/order.go`：

| 角色 | 可见范围 |
|------|---------|
| 话务员 / 话务员管理员 | 只能看到**自己录入**（`created_by`）的订单 |
| 收单员 | 只能看到**派给自己**（`agent_id`）的订单 |
| 收单员管理员 / 文员 / 管理员 / 超管 | 可看到**全部**订单 |

### 3.4 操作权限矩阵（前端 `canCollect` / 后端双校验）

前端 `pages/order/detail/index.vue` 的 `canCollect` 与后端 `bizorder/perm.go`、`staff/order.go` 保持一致：

| 操作 | 允许角色 |
|------|---------|
| 排单（步骤2） | 收单员管理员 / 超管 |
| 预约（步骤3）、收单（步骤4）/ 编辑收单 | 收单员 / 收单员管理员 / 超管 |
| 完工（步骤6） | 文员 / 管理员 / 超管；**订单需已收单（status≥4），未收单不可完工（含文员/管理员/超管）** |
| 录单（PC 端） | 话务员 / 话务员管理员 / 管理员 / 超管 |
| 回访（步骤5，PC 端） | 话务员 / 话务员管理员 / 超管 |

**关键限制：**
- **收单员管理员**可查看全部订单，但**预约/收单仅限收单员为自己**（`agent_id == 当前用户ID`）的订单；排单不受限。后端在 `StepEdit`/`StepNext` 中通过 `canAgentManagerAppointCollect` 强制校验。
- **管理员 / 文员**不参与排单、预约、收单等运营操作（小程序端 `forbidOperational` 拦截；仅查看与完工）。
- **话务员**在小程序端仅查看；录单、回访在 PC 管理端完成。

## 4. 订单状态与流转

### 4.1 状态枚举（`server/internal/consts/order.go`）

| 值 | 名称 | 含义 |
|----|------|------|
| 0 | 未成交 | 终止态（预留） |
| 1 | 已录单 | 话务员已录入（=待排单） |
| 2 | 已接单 | 已指派收单员（=待预约） |
| 3 | 已预约 | 已与客户预约（=待收单） |
| 4 | 已上门 | 收单员已上门（=已收单） |
| 5 | 已回访 | 话务员已二次回访 |
| 6 | 已完工 | 流程结束 |

### 4.2 流转链路

```
录单(1) → 排单(2) → 预约(3) → 收单(4) → 回访(5) → 完工(6)
```

每个步骤对应一个 `step`（1~6），`StepEdit` 保存本步骤字段，`StepNext` 推进状态（`status+1`）。

### 4.3 标签配色（`components/order-tag/order-tag.vue`）

| 状态 | 颜色 | 底色 |
|------|------|------|
| 0 未成交 | 灰 `#8B8C8F` | `#F0F0F0` |
| 1 已录单 / 2 待预约 | 橙 `#FE8B00` | `#FDE9B1` |
| 3 待收单 | 红 `#D92400` | `#FFDED6` |
| 4 已收单 / 5 已回访 / 6 已完工 | 蓝 `#1F61FF` | `#D0E3FF` |

> 设计语义：**未收单状态（已录单/待预约）用橙、待收单用红（紧急度最高）、已收单及之后用蓝**，与首页统计 tab 强调色一致。

## 6. 业务接口设计

### 6.1 认证

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/staff/auth/login` | 登录（用户名+密码），返回 `accessToken` + `refreshToken` |
| POST | `/staff/auth/refresh` | 用 refreshToken 换新 accessToken |
| GET | `/staff/user/profile` | 当前用户信息（含 `roleKey`） |

### 6.2 订单

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/staff/order/list` | 订单列表（按角色过滤可见范围） |
| GET | `/staff/order/stat` | 订单统计（按角色返回对应 tab 数值） |
| GET | `/staff/order/view` | 订单详情（含话务员/收单员姓名） |

### 6.3 步骤操作

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/staff/order/schedule` | 排单（步骤2，选择收单员） |
| POST | `/staff/order/appoint` | 填写预约情况（步骤3） |
| POST | `/staff/order/collect` | 填写收单情况（步骤4，`finish=true` 时推进状态） |
| POST | `/staff/order/complete` | 完工（步骤6） |

### 6.4 详细情况（评论区）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/staff/order/detailList` | 订单详细情况列表 |
| POST | `/staff/order/detailAdd` | 新增详细情况 |
| POST | `/staff/order/detailDelete` | 删除（逻辑删除，仅本人记录） |

### 6.5 附件 / 其它

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/admin/attachment/listByIds` | 后台按附件 ID 列表获取附件对象（PC 组件回显用） |
| POST | `/admin/upload/file` | 附件上传（复用管理端） |
| GET | `/site/dict/data` | 数据字典（区县等） |

> **附件存储与回显约定（两端统一）**：`xy_biz_order.attachment_id` 只存**逗号分隔的数字附件 ID**；订单列表/详情接口**联查 `sys_attachment`**，额外返回 `attachments: [{id,url,name,size,mimetype}]`。PC 与小程序的编辑组件均存 ID，展示直接用接口返回的 `attachments` 对象（`resolveUrl` 拼 `ASSET_URL` 回显）。

## 7. 关键交互设计

### 7.1 订单卡片（`components/order-card`）

展示：客户姓名 + 状态标签、预约时间、办理地址（可复制）、**收单员：姓名（无则 `-`）**、话务员（详情页主卡）。列表页与查询页共用该组件。

### 7.2 详情页操作按钮（按角色 + 状态动态显隐）

`pages/order/detail/index.vue` 的 `actions` 计算：

| 订单状态 | 操作按钮 | 角色限制 |
|---------|---------|---------|
| 1 已录单 | 排单 | 收单员管理员 / 超管 |
| 2 已接单 | 填写预约情况 | `canCollect` |
| 3 已预约 | 填写收单情况 | `canCollect` |
| 4 已上门 | 编辑收单 | `canCollect` |
| 5 已回访 | 完工 | 文员 / 管理员 / 超管（已收单 status≥4 可完工，未收单 status<4 不可完工） |

`canCollect`：收单员/超管放行；收单员管理员仅当 `order.agentId === 当前用户ID`。

### 7.3 预约 / 收单弹层

- 预约：填写「收单预约情况」→ 提交 `/order/appoint`，状态为已接单时自动推进到已预约。
- 收单：填写上门日期、成交业务、携转、客户实名、实缴、是否乡下单、新开号码、终端串码、话补、附件等 → 提交 `/order/collect`，`finish=true` 且状态为已预约时推进到已上门。

### 7.4 排单选择收单员

`/staff/user/agents` 返回启用中的收单员列表（`id` + 姓名，`agent` 角色、`status=1`），排单页选择后提交 `/order/schedule`。

### 7.5 附件上传与回显

- 上传：`/admin/upload/file`，返回 `attachmentId`（数字）。
- 存储：`attachment_id` 存逗号分隔的数字 ID；订单接口联查返回 `attachments` 对象。
- 回显：`resolveUrl`（`utils`）拼 `ASSET_URL` —— H5 跨域指向统一后端网关（`VITE_H5_API_BASE`），小程序端为配置的服务器地址。

## 8. 认证与会话

`utils/request.js`：

- **双令牌**：`xygo_staff_token`（accessToken）+ `xygo_staff_refresh_token`（refreshToken，持久化）。
- **自动续期**：业务返回 `code 61`（登录失效）时，先调 `/staff/auth/refresh` 换新 token 并**重放原请求**（单次重试，`_retried` 标记）。
- **单飞刷新**：并发多个 401 时共享同一个刷新 Promise（`refreshPromise`），避免重复刷新。
- **登录失效 / 重放仍失败**：清除双 token，toast 后端提示，`reLaunch` 到登录页。
- **被踢下线（`code 10010`）**：不尝试刷新（后端已删除旧 refreshToken），直接清会话回登录页。
- 状态码常量：`CODE_SUCCESS=0`、`CODE_UNAUTHORIZED=61`、`CODE_KICKED_OUT=10010`（与后端 `consts/code.go` 对齐）。

## 9. 构建与部署

### 9.1 构建命令（`uniapp/xygouniapp/`）

```bash
npm run dev:h5              # H5 开发（默认 :5173，代理 /staff /admin /attachment /site）
npm run build:h5            # H5 构建 → dist/build/h5/
npm run dev:mp-weixin       # 微信小程序开发
npm run build:mp-weixin     # 微信小程序构建 → dist/build/mp-weixin/
```

### 9.2 环境变量（`.env` / `.env.development` / `.env.production`）

- `VITE_API_BASE`：**小程序端**（mp-weixin/App）API 基地址，构建时注入 `import.meta.env.VITE_API_BASE`。
- `VITE_H5_API_BASE`：**H5 端** API/图片基地址（跨域调用统一后端网关 3006）；开发态留空，H5 走 vite 代理同源。
- 覆盖方式：编辑 `.env.production` 或构建时以 shell 环境变量注入（优先级更高）。

### 9.3 部署架构（统一后端网关 + H5 独立静态）

- **3006 = 统一后端网关 + 管理后台**（`deploy/nginx.fpd.conf`）
  - 管理后台静态 `location /` → `/home/fpd/web/`。
  - API 代理：`/staff/`、`/admin/`、`/attachment/`、`/site/`、`/system/`、`/captcha/`、`/member/`、`/socket/` → `http://127.0.0.1:4096`。
  - `client_max_body_size 20m`（附件上传）。
  - 正式微信包与 H5 跨域请求均以完整地址打到这里。
- **3007 = 小程序 H5 纯静态**（`deploy/nginx.uni.conf`）
  - 仅 `location /` → `/home/fpd/m/`（H5 构建产物，router base `/`），无任何代理。
  - H5 的 API/图片由前端跨域调用 3006。
- **CORS**：后端已有 `middleware.CORS`（覆盖 `/staff` `/admin` `/site`，预检 OPTIONS 在鉴权前返回 204，允许 `Authorization` 头）。按环境在 `server/manifest/config/config.yaml` 的 `security.corsOrigins` 维护白名单：开发留空（全来源放行）；生产加入 H5 来源（如 `http://81.71.150.152:3007` 或对应域名）。微信原生请求无 `Origin` 头，不受影响。无需在 nginx 重复配置 CORS。

部署步骤：
1. H5 构建产物部署到服务器 `/home/fpd/m/`。
2. 加载 `nginx.fpd.conf`（3006）与 `nginx.uni.conf`（3007）→ `sudo nginx -t` → `sudo nginx -s reload`。
3. 验证 `curl -sI http://<host>:3007/` 返回 200；H5 页面接口/图片跨域到 3006 正常。

### 9.4 微信小程序注意事项

- 正式发布要求 **HTTPS + 配置合法域名，且域名不能带端口/IP**。
- 届时把 3006 的 `listen` 改为 `443 ssl` + 证书（或另加 443 server），`VITE_API_BASE` 换成 `https://你的域名`；代理路径不变，正式环境仅一个入口。
- 上传（`uploadFile` 合法域名）、图片（`downloadFile`/图片 合法域名）、请求（`request` 合法域名）可都填该 HTTPS 域名。
- 开发者工具联调（`urlCheck:false`）可直接用 `http://81.71.150.152:3006`。
